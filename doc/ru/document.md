# Структура исходного текста документа

Документ состоит из одного или более файлов в формате [Markdown]. Файлы
могут включать в себя [другие файлы](#include). Корневой файл документа
называется _главным_.

## Параметры документа

Каждый файл может содержать в себе преамбулу в формате [YAML], которая 
позволяет задать параметры документа. Преамбула должна начинаться и
заканчиваться строкой из трех дефисов. Все параметры опциональны.

`lang`
:  Язык документа в формате [RFC 5646](https://tools.ietf.org/html/rfc5646),
   например `en-US` или `ru-RU`.

`title`
:  Заголовок документа. Используется для титульной страницы PDF формата, а также
   в свойствах PDF документа.

`subtitle`
:  Подзаголовок документа. Используется для титульной страницы PDF формата, а 
   также в свойствах PDF документа.

`author`
:  Автор документа. Используется для титульной страницы PDF формата, а также
   в свойствах PDF документа.

`version`
:  Версия документа. Используется для титульной страницы PDF формата.

`keywords`
:  Ключевые слова документа. Используются в свойствах PDF документа и в 
   метаданных HTML документа. Могут определяться массивом или строкой.

`date`
:  Дата модификации документа. Используется в свойствах PDF документа и в 
   метаданных HTML документа. Может быть задана в формате `YYYY-MM-DD` или
   `YYYY-MM-DD HH:MM:SS`.

`confluence`
:  Словарь параметров для публикации в Confluence. Содержит следующие ключи:

   `server`
   :  URL сервера Confluence (например, `https://confluence.example.com`).

   `space`
   :  Ключ пространства Confluence (например, `PROJ`).

   `path`
   :  Путь к странице. Может быть строкой или массивом строк.

      Если `path` — строка, она используется как заголовок страницы,
      размещаемой непосредственно в корне пространства.

      Если `path` — массив, последний элемент используется как заголовок
      создаваемой страницы, остальные — как цепочка предков. Каждый элемент
      может быть заголовком страницы или литеральным ID в формате
      `id:12345678`.

Все параметры являются опциональными.

Любой параметр преамбулы может быть переопределён при сборке с помощью флагов
`--meta` и `--meta-drop` (см. [Переопределение метаданных](builder/index.md#переопределение-метаданных)).

Пример:

~~~markdown
‑‑‑
title:    Система подготовки документации
author:   Example
lang:     ru-RU
version:  0.1.0
keywords: documentation, markdown, internal tools
confluence:
  server: https://confluence.example.com
  space:  PROJ
  path:
    - "Родительская страница"
    - "Название документа"
‑‑‑
~~~

Параметры документа берутся из YAML-преамбулы главного файла документа.

## Включение файлов {#include}

Файлы могут включать в себя другие файлы при помощи специального блока
`include`, который должен содержать ссылки на другие файлы внутри проекта. 
Наименование ссылок является справочным для удобства и не влияет на
результирующий документ.

Ссылки внутри блока `include` должны быть в форме заголовков [Markdown].
При этом, уровень заголовка определяет сдвиг уровней заголовков включаемого
файла. Например, если для включения файла используется заголовок второго уровня,
то все заголовки внутри него будут сдвинуты на один уровень вниз.

Предположим, что у нас есть структура проекта следующего вида

`project`

:   ~~~plantuml
    @startsalt
    {
        {T
         + project/
         ++ hld/
         +++ arch.md
         +++ index.md
         ++ index.md
        }
    }
    @endsalt
    ~~~

`project/index.md`

:   ~~~markdown
    # Назначение системы

    :::include
    # [HLD](hld/index.md)
    :::
    ~~~

`project/hld/index.md`

:   ~~~markdown
    # High-level design

    :::include
    ## [Architecture](arch.md)
    :::
    ~~~

`project/hld/arch.md`

:   ~~~markdown
    # Архитектура

    ## Базовые принципы
    ~~~

В результате получится следующая структура:

~~~markdown
# Назначение системы

# High-level design

## Архитектура

### Базовые принципы
~~~
