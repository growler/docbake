# Форматы вывода

Сборщик поддерживает несколько форматов:

`html`

: Линейная HTML-страница со всем содержимым.

`html-multi`

: Набор HTML-страниц, отображающий структуру исходного 
  документа (каждый `.md` документ станет отдельной
  страницей)

`pdf`

: PDF-документ, генерируемый при помоищи системы верстки 
  [`typst`](https://typst.app/)

`markdown`

: Линейный Markdown-документ со всем содержимым, после 
  обработки всех блоков `include`. Может быть полезным 
  для AI-агентов.

## Блоки для использования в конкретном формате

В некоторых случаях отдельные фрагменты текста должны отображаться 
только в конкретном формате. Например, назначение документа может
требоваться в PDF документе, но не в HTML. В таких случаях можно
указывать класс фрагмента:

~~~markdown
:::pdf
# Назначение документа

Этот блок будет отображаться только в PDF документе.
:::
~~~

Можно указывать несколько классов. Поддерживаемые форматы: `html` и `pdf`.

~~~markdown
:::{.html .pdf}
# Назначение документа

Этот блок будет отображаться в HTML и PDF документах.
:::
~~~

## HTML {#html}

Сборщик генерирует single-page HTML документ, в котором всё содержимое
(включая стили) встроено в один файл. Файлы изображений и другие ресурсы
копируются в подкаталог `static` каталога вывода, а ссылки на них в HTML
переписываются соответственно.

### Шаблон HTML

HTML-страница генерируется с помощью шаблонизатора [Tera](https://keats.github.io/tera/).
Шаблон берётся из файла `template.html` [каталога темы](config.md#theme-dir).

Шаблон получает следующие переменные:

`title`
:  Заголовок документа из метаданных.

`subtitle`
:  Подзаголовок документа (если задан).

`lang`
:  Язык документа (например, `ru-RU`). По умолчанию `en`.

`date`
:  Дата документа (если задана).

`authors`
:  Массив авторов документа (если задан).

`abstract`
:  Аннотация документа (если задана), уже в формате HTML.

`abstract_title`
:  Заголовок аннотации. По умолчанию `Abstract`.

`style`
:  Содержимое файла `style.css` из каталога темы (если файл присутствует).
   Выводится с фильтром `| safe`, поскольку содержит CSS-код.

`body`
:  Отрендеренный HTML-код тела документа. Выводится с фильтром `| safe`.

`toc`
:  Таблица содержания в виде вложенных `<ul>/<li>` элементов.
   Выводится с фильтром `| safe`.

`front_matter`
:  Объект со всеми метаданными из YAML-преамбулы документа.

`asset_prefix`
:  Относительный путь к корню вывода. Для single-page HTML — пустая строка.
   Для multi-page HTML — вычисляется для каждой страницы (например, `../`).
   Используется для ссылок на файлы из каталога `assets/` темы.

### Пример шаблона HTML

~~~html
<!DOCTYPE html>
<html lang="{{ lang }}">
<head>
  <meta charset="utf-8" />
  <title>{{ title }}</title>
  <style>{{ style | safe }}</style>
</head>
<body>
  {% if title %}
  <header>
    <h1 class="title">{{ title }}</h1>
    {% if subtitle %}<p class="subtitle">{{ subtitle }}</p>{% endif %}
  </header>
  {% endif %}

  <nav id="toc" role="doc-toc">
    {{ toc | safe }}
  </nav>

  <main>
    {{ body | safe }}
  </main>
</body>
</html>
~~~

### Таблица содержания

Таблица содержания генерируется автоматически из всех заголовков документа
(включая заголовки из включённых файлов). Заголовки с классом `.unlisted`
исключаются из таблицы содержания. Заголовки с классом `.unnumbered`
включаются, но не нумеруются.

### Подсветка синтаксиса

В HTML выводе блоки кода с указанным языком подсвечиваются автоматически.
Стили подсветки встроены в HTML.

### Сноски

Сноски собираются в конце документа в блоке `<div class="footnotes">` с
обратными ссылками на места их использования.

## PDF {#pdf}

Сборщик генерирует PDF через промежуточное представление в формате Typst.
Сначала содержимое документа транслируется в Typst-разметку, затем 
формируется итоговый `.typ` файл по шаблону, и далее вызывается внешняя
команда `typst compile` для создания PDF.

Для работы PDF-вывода необходимо, чтобы `typst` был установлен и доступен
в `PATH` (см. [Инсталляция](index.md#инсталляция)).

### Шаблон PDF

PDF-шаблон также обрабатывается шаблонизатором [Tera](https://keats.github.io/tera/),
но результат представляет собой Typst-разметку, а не HTML.

Шаблон получает те же переменные метаданных, что и HTML (`title`, 
`subtitle`, `lang`, `date`, `author`, `version` и т.д.), а также:

`body`
:  Отрендеренный Typst-код тела документа. Выводится с фильтром `| safe`.

`lang`
:  Код языка (без региона), например `ru`. По умолчанию `en`.

`region`
:  Код региона (если указан в метаданных), например `RU`.

`asset_prefix`
:  Относительный путь к корню вывода (для PDF — всегда пустая строка).

Шрифты, цвета, пути к ресурсам (например, логотипу) и другие
оформительские параметры задаются непосредственно в шаблоне `template.typ`.
Для создания собственного оформления экспортируйте встроенную тему
командой `docbake init-theme` и отредактируйте файл.

### Пример шаблона PDF

~~~typst {.as-code}
#set page(paper: "a4", margin: 2cm)
#set text(lang: "{{ lang | default(value="en") }}", size: 11pt)

{% if title %}
#align(center, text(size: 22pt, weight: "bold", "{{ title }}"))
{% endif %}
{% if author %}
#align(center, text(size: 12pt, "{{ author }}"))
{% endif %}

{{ body | safe }}
~~~

### Особенности PDF вывода

- Сноски размещаются внизу соответствующей страницы (стандартное поведение
  Typst `#footnote[...]`).
- Inline HTML игнорируется — используйте только Markdown-разметку.
- Ссылки на метки внутри документа транслируются в Typst-ссылки на labels
  (`#link(<label>)[...]`). Если метка не найдена, ссылка выводится как
  простой текст.
- Подписи таблиц и диаграмм оформляются как `#figure(caption: [...])`.
- Подписи блоков кода (`Listing:`) оформляются как
  `#figure(kind: raw, caption: [...])` и нумеруются отдельно от
  таблиц и рисунков с префиксом «Листинг» (или «Listing» для
  английского языка).
- Блоки кода оформляются функцией `#raw()` с указанием языка.

## Markdown {#format-markdown}

Формат Markdown генерирует единый Markdown-файл, полученный после раскрытия
всех `:::include` директив, переписывания ссылок, сборки сносок и
нормализации уровней заголовков. Этот формат полезен для отладки и для
экспорта документа в системы, работающие с обычным Markdown.

~~~
$ docbake build -f markdown -i doc/ru/index.md -o target/doc-out/ -b doc
~~~
