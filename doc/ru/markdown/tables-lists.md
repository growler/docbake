# Таблицы и списки

## Таблицы

Таблицы используют синтаксис pipe-таблиц. Ячейки разделяются символом
`|`, выравнивание колонок задается символом `':'` в строке разделителя:

~~~markdown
Позиция | Цена
:-------|----:
SRV-001 |  100
SRV-002 |  200
~~~

:::related
# Результат

Позиция | Цена
:-------|----:
SRV-001 |  100
SRV-002 |  200
:::

### Подпись таблицы

Для того чтобы таблицу можно было адресовать, надо обязательно
указать подпись. Подпись может быть задана в виде отдельного параграфа
до или после таблицы, начинающегося со слова `Table:` (или `table:`).
Аналогичные префиксы используются для блоков кода (`Listing:`) и
рисунков (`Figure:`).

~~~markdown
Table: Применяемые стандарты

| RFC      | Описание                |
|----------|-------------------------|
| RFC 2822 | Internet Message Format |

...

Стандарты указаны в [таблице](# "Применяемые стандарты")
~~~

:::related
# Результат

Table: Применяемые стандарты

| RFC      | Описание                |
|----------|-------------------------|
| RFC 2822 | Internet Message Format |

...

Стандарты указаны в [таблице](# "Применяемые стандарты")
:::

Идентификатор таблицы можно указать явно в следующем формате:

~~~markdown
Table: Применяемые стандарты {#rfc-table}

| RFC      | Описание                |
|----------|-------------------------|
| RFC 2822 | Internet Message Format |

...

Стандарты указаны в [таблице](#rfc-table)
~~~

## Списки

Формат позволяет описывать несколько видов списков.

### Ненумерованные списки (bullet lists)

Элемент ненумерованного списка начинается с символа `*`, `+` или `-`:

Если каждый элемент списка начинается с новой строки, то представление
списка будет компактным:

~~~markdown
* Элемент 1
* Элемент 2
* Элемент 3
~~~

:::related
# Результат

* Элемент 1
* Элемент 2
* Элемент 3
:::

Если разделить элементы списка пустой строкой, то получится список, где
каждый элемент представлен отдельным параграфом. В элементах такого
списка также можно использовать другие блочные элементы разметки.

~~~markdown
* Элемент 1

* Элемент 2

  ```
  code
  ```

* Элемент 3
~~~

:::related
# Результат

* Элемент 1

* Элемент 2

  ```
  code
  ```

* Элемент 3
:::

Формат также позволяет описывать вложенные списки:

~~~markdown
* Элемент 1
  + Элемент 1.1
  + Элемент 1.2
* Элемент 2
~~~

:::related
# Результат

* Элемент 1
  + Элемент 1.1
  + Элемент 1.2
* Элемент 2
:::

Разделять элементы списка пустой строкой в этом случае не обязательно.

### Нумерованные списки (ordered lists)

Элемент нумерованного списка начинается с числа, за которым следует точка
или закрывающая скобка. Номер первого элемента определяет начальное значение
нумерации.

~~~markdown
1. Элемент 1
   1. Элемент 1.1
   2. Элемент 1.2
2. Элемент 2
~~~

:::related
# Результат

1. Элемент 1
   1. Элемент 1.1
   2. Элемент 1.2
2. Элемент 2
:::

### Списки определений (definition lists)

Списки определений состоят из пар "термин" и "определение". 
Каждый термин должен помещаться на одной строке, которая может быть дополнена 
пустой строкой, и должен сопровождаться одним или несколькими определениями. 
Определение начинается с двоеточия `:`, которое может быть с отступом
в один или два пробела.

Если между термином и определением есть пустая строка, то определение будет
оформлено отдельным параграфом. Кроме того, в нем можно использовать другие
блочные элементы разметки, выделенные четырьмя пробелами.

~~~markdown
Термин

:  Определение

    ```
    code example
    ```
~~~

:::related
# Результат

Термин

:  Определение

    ```
    code example
    ```
:::

Если пустой строки нет, то определение будет оформлено как inline-элемент и 
в нем можно использовать только inline-разметку. Такой формат также выглядит
более компактным в тексте и удобен, если термины и определения короткие.

~~~markdown
Термин
:  Определение

Термин
:  Определение
~~~

:::related
# Результат

Термин
:  Определение

Термин
:  Определение
:::

### Списки с чекбоксами (task lists)

Элементы списка могут содержать чекбоксы. Для этого после маркера списка
указывается `[ ]` (не отмечено) или `[x]` (отмечено):

~~~markdown
- [x] Задача выполнена
- [ ] Задача не выполнена
- [ ] Ещё одна задача
~~~

:::related
# Результат

- [x] Задача выполнена
- [ ] Задача не выполнена
- [ ] Ещё одна задача
:::
