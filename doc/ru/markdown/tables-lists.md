# Таблицы и списки

## Таблицы

Таблицы используют синтаксис pipe-таблиц. Ячейки разделяются символом `|`,
выравнивание колонок задается символом `':'` в строке разделителя:

~~~markdown
Позиция | Цена
:-------|----:
SRV-001 |  100
SRV-002 |  200
~~~

:::related
# Результат

Позиция | Цена
:------ | ---:
SRV-001 |  100
SRV-002 |  200
:::

### Подпись таблицы

Для того чтобы таблицу можно было адресовать, надо обязательно указать подпись.
Подпись может быть задана в виде отдельного параграфа до или после таблицы,
начинающегося со слова `Table:` (или `table:`). Аналогичные префиксы
используются для блоков кода (`Listing:`) и рисунков (`Figure:`).

~~~markdown
Table: Применяемые стандарты

| RFC      | Описание                |
| -------- | ----------------------- |
| RFC 2822 | Internet Message Format |

...

Стандарты указаны в [таблице](# "Применяемые стандарты")
~~~

:::related
# Результат

Table: Применяемые стандарты

| RFC      | Описание                |
| -------- | ----------------------- |
| RFC 2822 | Internet Message Format |

...

Стандарты указаны в [таблице](# "Применяемые стандарты")
:::

Идентификатор таблицы можно указать явно в следующем формате:

~~~markdown
Table: Применяемые стандарты {#rfc-table}

| RFC      | Описание                |
| -------- | ----------------------- |
| RFC 2822 | Internet Message Format |

...

Стандарты указаны в [таблице](#rfc-table)
~~~

### Многострочные таблицы

Многострочные таблицы позволяют заголовкам и строкам тела занимать несколько
физических строк. Строки тела разделяются пустой строкой. Синтаксис совместим со
стандартом [Pandoc multiline tables].

**Таблица с заголовком.** Сплошная линия из дефисов открывает таблицу. Затем
идут строки заголовка. Линия-разделитель с группами дефисов (разделёнными
пробелами) задаёт ширину и выравнивание столбцов. Тело таблицы завершается ещё
одной сплошной линией:

~~~markdown
-------------------------------------------------------------------
  Выровнен   По         Вправо Влево
  по центру  умолчанию
------------ --------- ------- ------------------------------------
  Первая      строка      12.0 Пример строки, которая
                               занимает несколько физических строк.

  Вторая      строка       5.0 Ещё одна строка. Обратите внимание
                               на пустую строку между строками.
-------------------------------------------------------------------

Table: Пример многострочный таблицы 
~~~

:::related
# Результат

-------------------------------------------------------------------
  Выровнен   По         Вправо Влево
 по центру   умолчанию
------------ --------- ------- ------------------------------------
   Первая    строка       12.0 Пример строки, которая
                               занимает несколько физических строк.

   Вторая    строка        5.0 Ещё одна строка. Обратите внимание
                               на пустую строку между строками.
-------------------------------------------------------------------

Table: Пример многострочный таблицы
:::

**Таблица без заголовка.** Если таблица начинается с линии-разделителя (а не со
сплошной линии), строки заголовка отсутствуют, и все строки считаются строками
тела. Выравнивание в этом случае определяется по первой строке тела.

~~~markdown
------------ ----------- ------- ------------------------------------
Первая       строка         12.0 Пример многострочной строки без
                                 заголовка.

Вторая       строка          5.0 Ещё одна строка.
---------------------------------------------------------------------

Table: Пример таблицы без заголовка 
~~~

:::related
# Результат

------------ ----------- ------- ------------------------------------
Первая       строка         12.0 Пример многострочной строки без
                                 заголовка.

Вторая       строка          5.0 Ещё одна строка.
---------------------------------------------------------------------

Table: Пример таблицы без заголовка
:::

Ширина столбцов в источнике влияет на вывод: если текст в столбце слишком
широкий в PDF или HTML, достаточно расширить группу дефисов в линии-разделителе.

Подпись добавляется в виде параграфа `Table:` до или после таблицы (см.
[«Подпись таблицы»](# "Подпись таблицы")).

[Pandoc multiline tables]: https://pandoc.org/demo/example33/8.9-tables.html

### Grid-таблицы

Grid-таблицы используют символы `+`, `-`, `=` и `|` для рисования границ ячеек.
В отличие от многострочных таблиц, ячейки явно обведены рамкой, поэтому
содержимое ячейки может занимать произвольное число физических строк, а столбцы
могут объединяться (см. ниже). Синтаксис совместим со стандартом
[Pandoc grid tables].

**Базовый вид.** Верхняя и нижняя границы — обязательны. Заголовок отделяется от
тела строкой `+===+...+===+` (символ `=` вместо `-`). Если такой строки нет,
таблица считается безголовочной, и все строки — это строки тела.

~~~markdown
+----------------+----------------+--------------------+
| Фрукт          | Цена           | Преимущества       |
+================+================+====================+
| Бананы         | 100 ₽          | в фирменной упаковке |
+----------------+----------------+--------------------+
| Апельсины      | 150 ₽          | защищают от цинги    |
+----------------+----------------+--------------------+

Table: Простая grid-таблица
~~~

:::related
# Результат

+----------------+----------------+----------------------+
| Фрукт          | Цена           | Преимущества         |
+================+================+======================+
| Бананы         | 100 ₽          | в фирменной упаковке |
+----------------+----------------+----------------------+
| Апельсины      | 150 ₽          | защищают от цинги    |
+----------------+----------------+----------------------+

Table: Простая grid-таблица
:::

**Многострочные ячейки.** Если две соседние строки тела не разделены
горизонтальной линией `+---+...+---+`, они объединяются в одну логическую строку
с многострочным содержимым.

~~~markdown
+--------------+--------------------------------+
| Параметр     | Описание                       |
+==============+================================+
| `max-retry`  | Максимальное число повторов при |
|              | временной ошибке. По умолчанию  |
|              | равно `3`.                      |
+--------------+--------------------------------+
| `timeout`    | Тайм-аут одного запроса в       |
|              | миллисекундах.                  |
+--------------+--------------------------------+
~~~

:::related
# Результат

+--------------+---------------------------------+
| Параметр     | Описание                        |
+==============+=================================+
| `max-retry`  | Максимальное число повторов при |
|              | временной ошибке. По умолчанию  |
|              | равно `3`.                      |
+--------------+---------------------------------+
| `timeout`    | Тайм-аут одного запроса в       |
|              | миллисекундах.                  |
+--------------+---------------------------------+
:::

**Выравнивание столбцов.** Маркеры `:` рядом с `+` в любой строке-разделителе
задают выравнивание соответствующего столбца: `+:--+` — по левому краю, `+--:+`
— по правому, `+:-:+` — по центру, `+---+` — по умолчанию. Выравнивание берётся
из первой строки-разделителя, в которой встречаются маркеры (как правило, это
строка `+===+`).

~~~markdown
+----------+----------+------------+
| Слева    | Справа   | По центру  |
+:=========+=========:+:==========:+
| a        | b        | c          |
+----------+----------+------------+
~~~

:::related
# Результат

+----------+----------+------------+
| Слева    | Справа   | По центру  |
+:=========+=========:+:==========:+
| a        | b        | c          |
+----------+----------+------------+
:::

**Объединённые ячейки (column spans).** Чтобы объединить несколько столбцов в
одну ячейку, опустите символ `|` на границах объединяемых столбцов в строке с
содержимым. Внешние `|` в начале и конце строки обязательны. Все физические
строки одной логической строки должны использовать одни и те же позиции
разделителей.

В примере ниже объединены ячейки одновременно в заголовке (`Контактные данные`
покрывает столбцы 2–3) и в теле (последняя строка объединяет все три столбца под
итоговым комментарием):

~~~markdown
+--------------+---------------+--------------+
| Сотрудник    | Контактные данные            |
+--------------+---------------+--------------+
| Имя          | Email         | Телефон      |
+==============+===============+==============+
| Иванов И.И.  | iv@example.ru | +7 495 000-1 |
+--------------+---------------+--------------+
| Петров П.П.  | pp@example.ru | +7 495 000-2 |
+--------------+---------------+--------------+
| Все данные актуальны на 1 января            |
+--------------+---------------+--------------+

Table: Объединённые ячейки в заголовке и теле
~~~

+--------------+---------------+--------------+
| Сотрудник    | Контактные данные            |
+--------------+---------------+--------------+
| Имя          | Email         | Телефон      |
+==============+===============+==============+
| Иванов И.И.  | iv@example.ru | +7 495 000-1 |
+--------------+---------------+--------------+
| Петров П.П.  | pp@example.ru | +7 495 000-2 |
+--------------+---------------+--------------+
| Все данные актуальны на 1 января            |
+--------------+---------------+--------------+

:::

**Объединённые строки (row spans).** Чтобы ячейка занимала несколько строк
по вертикали, в линии-разделителе после неё на месте символов `-` оставьте
пробелы. `+` на границах столбцов должны сохраняться — pandoc требует, чтобы
линия-разделитель содержала `+` в тех же позициях, что и верхняя граница
таблицы.

В примере ниже ячейка `Иванов И.И.` объединяет две строки: основную и строку
с дополнительной телефонной строкой. Линия-разделитель `+              +    +`
показывает, что левый столбец продолжается (пробелы вместо дефисов),
а правый закрывается.

~~~markdown
+--------------+-----------------+
| Сотрудник    | Контакт         |
+==============+=================+
| Иванов И.И.  | iv@example.ru   |
+              +-----------------+
|              | +7 495 000-1    |
+--------------+-----------------+
| Петров П.П.  | pp@example.ru   |
+--------------+-----------------+

Table: Сотрудник с двумя строками контакта
~~~

:::related
# Результат

+--------------+-----------------+
| Сотрудник    | Контакт         |
+==============+=================+
| Иванов И.И.  | iv@example.ru   |
+              +-----------------+
|              | +7 495 000-1    |
+--------------+-----------------+
| Петров П.П.  | pp@example.ru   |
+--------------+-----------------+

Table: Сотрудник с двумя строками контакта
:::

::: note
Объединение строк не может пересекать границу `+===+` между заголовком и
телом таблицы. Внутри ячеек разрешено только встроенное форматирование
(`**bold**`, `*em*`, `` `code` `` и т.д.) — вложенные списки, блоки кода
и многоабзацные ячейки рендерятся как встроенный текст.
:::

[Pandoc grid tables]: https://pandoc.org/demo/example33/8.9-tables.html

## Списки

Формат позволяет описывать несколько видов списков.

### Ненумерованные списки (bullet lists)

Элемент ненумерованного списка начинается с символа `*`, `+` или `-`:

Если каждый элемент списка начинается с новой строки, то представление списка
будет компактным:

~~~markdown
* Элемент 1
* Элемент 2
* Элемент 3
~~~

:::related
# Результат

* Элемент 1
* Элемент 2
* Элемент 3
:::

Если разделить элементы списка пустой строкой, то получится список, где каждый
элемент представлен отдельным параграфом. В элементах такого списка также можно
использовать другие блочные элементы разметки.

~~~markdown
* Элемент 1

* Элемент 2

  ```
  code
  ```

* Элемент 3
~~~

:::related
# Результат

* Элемент 1

* Элемент 2

  ```
  code
  ```

  -------------- ---------------
  A multiline             `true`
  table
  ------------------------------

* Элемент 3
:::

Формат также позволяет описывать вложенные списки:

~~~markdown
* Элемент 1
  + Элемент 1.1
  + Элемент 1.2
* Элемент 2
~~~

:::related
# Результат

* Элемент 1
  + Элемент 1.1
  + Элемент 1.2
* Элемент 2
:::

Разделять элементы списка пустой строкой в этом случае не обязательно.

### Нумерованные списки (ordered lists)

Элемент нумерованного списка начинается с числа, за которым следует точка или
закрывающая скобка. Номер первого элемента определяет начальное значение
нумерации.

~~~markdown
1. Элемент 1
   1. Элемент 1.1
   2. Элемент 1.2
2. Элемент 2
~~~

:::related
# Результат

1. Элемент 1
   1. Элемент 1.1
   2. Элемент 1.2
2. Элемент 2
:::

Нумеровать элементы внутри документа не обязательно, можно всегда использовать
одно число.

~~~markdown
1) Элемент 1
   1) Элемент 1.1
   1) Элемент 1.2
1) Элемент 2
~~~

:::related
# Результат

<!-- The formatter keeps renumbering so leave it be -->

1) Элемент 1
   1) Элемент 1.1
   2) Элемент 1.2
2) Элемент 2
:::

### Списки определений (definition lists)

Списки определений состоят из терминов и их определений. Термин занимает
отдельную строку. Следующая строка с определением начинается с двоеточия `:`;
перед двоеточием допустим отступ до трех пробелов, а после него должен идти хотя
бы один пробел или табуляция.

Термины нужно отделять от предыдущего определения пустой строкой. У одного
термина может быть несколько определений, и наоборот, одно определение может
относиться сразу к нескольким подряд идущим терминам.

Если между термином и определением нет пустой строки, определение записывается в
компактной форме и не выделяется в отдельный абзац. Это удобно для коротких
формулировок.

~~~markdown
Яблоко
:   Плод растений рода Malus.

Апельсин
:   Плод вечнозеленых деревьев рода Citrus.
~~~

:::related
# Результат

Яблоко
:   Плод растений рода Malus.

Апельсин
:   Плод вечнозеленых деревьев рода Citrus.
:::

Определение может занимать несколько строк. Продолжение удобно оформлять с
отступом, но это не обязательно.

~~~markdown
Яблоко
:   Плод растений рода Malus семейства Rosaceae.

Апельсин
:    Плод вечнозеленых деревьев рода Citrus,
который обычно имеет оранжевую кожуру.
~~~

:::related
# Результат

Яблоко
:   Плод растений рода Malus семейства Rosaceae.

Апельсин
:   Плод вечнозеленых деревьев рода Citrus, который обычно имеет оранжевую кожуру и
    округлую форму.
:::

Если перед определением есть пустая строка, его содержимое оформляется как
отдельный абзац. В таком определении можно использовать несколько абзацев и
другие блочные элементы.

~~~markdown
Термин

:   Это определение начинается с отдельного абзаца.

    Это второй абзац того же определения.

    ```
    code example
    ```

    | Header | Value |
    |--------|-------|
    | Table  | `nil` |
~~~

:::related
# Результат

Термин

:   Это определение начинается с отдельного абзаца.

    Это второй абзац того же определения.

    ```
    code example
    ```

    | Header | Value |
    | ------ | ----- |
    | Table  | `nil` |
:::

У одного термина может быть несколько определений:

~~~markdown
Яблоко
:   Плод растений рода Malus.
:   Название компании Apple в русскоязычных текстах иногда переводят буквально.
~~~

Несколько терминов тоже можно связать с одним определением:

~~~markdown
Термин 1
Термин 2
:   Общее определение.
~~~

### Списки с чекбоксами (task lists)

Элементы списка могут содержать чекбоксы. Для этого после маркера списка
указывается `[ ]` (не отмечено) или `[x]` (отмечено):

~~~markdown
- [x] Задача выполнена
- [ ] Задача не выполнена
- [ ] Ещё одна задача
~~~

:::related
# Результат

- [x] Задача выполнена
- [ ] Задача не выполнена
- [ ] Ещё одна задача
:::
