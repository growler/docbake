# Ссылки и сноски

## Ссылки

Ссылки внутри документа могут быть как абсолютными, начинающимися с `/`,
так и относительными. [Сборщик] определяет абсолютные ссылки от корня проекта[^vscode]. 
Простые ссылки определяются относительно файла, в котором они находятся. [Сборщик]
проверяет связность всех ссылок документа и выдает ошибку, если какая-либо 
ссылка указывает на несуществующую метку. Сборщик отслеживает все метки документа:
автоматические метки заголовков, подписей и блоков кода, а также ручные метки
(`{#id}`) на изображениях, диаграммах, строчных элементах (`[...]{#id}`) и блоках
(`:::{#id}`). Ссылка на несуществующую метку приводит к ошибке сборки.

К ссылкам на файлы изображений применяются те же правила.

Хотя [Сборщик] поддерживает абсолютные ссылки, рекомендуется использовать 
относительные ссылки, чтобы раздел документа был переносимым и мог быть 
включен в другой документ. Например, предположим, что у вас есть документы
**HLD** и **LLD**, каждый из которых имеет свой собственный главный файл.
Если ссылки внутри этих документов будут относительными, то возможно будет
определить новый документ "Комплект документации", который будет включать
в себя оба документа, и ссылки будут продолжать работать.

[Сборщик]: ../builder/index.md

[^vscode]: Visual Studio Code тоже определяет абсолютные ссылки в файлах Markdown
           от корня проекта, что делает VS Code удобным инструментом для редактирования
           документов.

Формат позволяет определять метки и ссылки несколькими способами.

### Метки 

Метки внутри документа используются для ссылок на разделы или элементы 
документа. Метки могут быть автоматическими, или заданными вручную.

Автоматические метки создаются из текста элемента (заголовка, рисунка, таблицы,
диаграммы или блока кода). Для этого текст приводится к нижнему регистру, из него
удаляются все символы, кроме букв, цифр и подчеркиваний, а пробелы и знаки 
препинания заменяются на дефис. Например, заголовок `Параметры документа` будет 
иметь метку `параметры-документа`. Для блоков кода автоматическая метка создается
из описательного текста в строке информации (см. 
[Расширенная строка информации](text.md#расширенная-строка-информации)).

Ручные метки задаются в расширенном синтаксисе Markdown посредством атрибутов 
элемента или подписи элемента:

~~~markdown
# Заголовок {#my-label}

![Рисунок](path/to/image.png){#my-label}

Table: Подпись таблицы {#my-label}

| Таблица ...

Figure: Подпись диаграммы {#my-label}

```plantuml
диаграмма...
```

```rust Описание блока кода
код получит метку из описания
```

```rust {#my-label}
код с явной меткой
```

:::{#my-label}
Раздел, требующий метки
:::

Просто [текст, требующий метки]{#my-label}
~~~

### Автоматические ссылки

URL или email-адрес в треугольных скобках автоматически преобразуются в ссылку:

~~~markdown
<https://example.com>
<someone@somewhere.net>
~~~

Результат:

<https://example.com>
<someone@somewhere.net>

### Inline ссылки

Inline ссылка состоит из текста, заключенного в квадратные скобки, и URL,
заключенного в круглые скобки и следующего непосредственно за текстом:

~~~markdown
[Текст ссылки](https://example.com)

[Раздел](#section)

[Раздел в документе](document.md#section)
~~~

Результат (с использованием реальных ссылок из этого документа):

[Внешняя ссылка](https://example.com)

[Раздел Заголовки](text.md#заголовки)

[Параметры документа](../document.md#параметры-документа)

Ссылка также может иметь заголовок:

~~~markdown
[Текст ссылки](https://example.com "Заголовок")
~~~

Результат: [Текст ссылки](https://example.com "Заголовок") — при наведении
курсора в HTML отображается подсказка. Заголовок транслируется в атрибут 
`title` HTML элемента `a`, но не используется в PDF выводе.

### Reference ссылки

Reference ссылка состоит из двух частей: определения ссылки и её использования.
Определение может быть указано в любом месте документа, как до, так и после
использования. Для удобства и ясности все определения ссылок лучше собирать
в конце фрагмента документа.

Определение ссылки состоит из двух частей: идентификатора ссылки и её URL с 
опциональным заголовком. Идентификатор ссылки заключается в квадратные скобки,
за которыми следует двоеточие, а затем URL ссылки. URL может заключаться 
в треугольные скобки. Заголовок ссылки может заключаться в двойные кавычки 
или круглые скобки.

~~~markdown
... как описано в [RFC 7763]

[RFC 7763]: https://www.rfc-editor.org/rfc/rfc7763.html "The text/markdown Media Type"
~~~

Результат: ... как описано в [RFC 7763]

[RFC 7763]: https://www.rfc-editor.org/rfc/rfc7763.html "The text/markdown Media Type"

### Ссылки внутри документа

Для ссылок внутри документа можно использовать следующий синтаксис:

~~~markdown
# Заголовок

[Ссылка на заголовок](#заголовок)

# Заголовок с идентификатором {#header-id}

[Ссылка на заголовок с идентификатором](#header-id)

[Ссылка на объект в другом документе](document.md#header-id)
~~~

Результат (с использованием реальных заголовков из этого документа):

[Ссылка на раздел Заголовки](text.md#заголовки)

[Ссылка на раздел с явным идентификатором](text.md#inline-markup)

[Ссылка на раздел в другом документе](../document.md#параметры-документа).

Также для удобства есть специальный синтаксис, который позволяет не
указывать автоматически созданный идентификатор. Для этого
необходимо в качестве ссылки указать символ `#`, а в качестве заголовка
ссылки написать текст, идентичный тому, из которого создается
идентификатор, но без дополнительных элементов форматирования:

~~~markdown
# Сложный _заголовок_ с `кодом`

[Ссылка на заголовок](# "Сложный заголовок с кодом")

[Ссылка на заголовок в другом документе](part/document.md "Заголовок в другом документе")
~~~

Результат (с использованием реального заголовка из другого документа):
[Ссылка на параметры](../document.md "Параметры документа").

Допускается также использовать только имя файла документа без указания 
конкретного идентификатора. В этом случае, ссылка будет указывать на
первый заголовок в документе:

~~~markdown
[Раздел](part/document.md)
~~~

Результат: [Структура документа](../document.md).

Наконец, для ссылок только на заголовки внутри документа можно использовать
сокращенный синтаксис:

~~~markdown
# Заголовок

... см. [Заголовок]
~~~

Результат (ссылка `[Сборщик]` с определением `[Сборщик]: builder/index.md`
в этом документе): см. [Сборщик].

## Сноски (footnotes) {#сноски}

Сноски позволяют добавлять примечания, не прерывая основной текст.
Синтаксис состоит из двух частей: ссылки на сноску в тексте и определения 
сноски.

Ссылка на сноску вставляется в тексте в формате `[^метка]`. Определение 
может находиться в любом месте документа и начинается с `[^метка]:`, 
за которым следует текст сноски.

Например, текст `утверждение[^note]` создаст ссылку на сноску `note`,
а определение этой сноски задаётся следующим образом:

    [^note]: Текст сноски.

Продолжение определения задаётся отступом. Допускается несколько параграфов:

    [^note]: Первый параграф.
    
        Второй параграф определения.

В тексте в месте ссылки на сноску появляется номер в виде надстрочного 
индекса[^fn-example]. В HTML выводе все сноски собираются в конце документа с 
обратными ссылками. В PDF выводе сноски размещаются внизу соответствующей 
страницы.

[^fn-example]: Вот так выглядит сноска.

Определения сносок могут находиться в том же файле, что и ссылки на них.
При сборке документа из нескольких файлов все сноски нумеруются последовательно
по всему документу.
